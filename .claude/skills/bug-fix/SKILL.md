# /bug-fix — Bug 定位与修复

触发场景：用户报告功能异常、报错信息或意外行为。

## 执行步骤

### 1. 复现与定位
- 明确 Bug 的触发步骤、错误信息（控制台报错 / 网络失败 / 渲染异常）。
- 阅读报错堆栈，定位到具体文件和行号。
- 若报错信息不充分，先添加临时 `console.error` / `console.warn` 确认数据流。

### 2. 根因分析
常见 Bug 类别及检查方向：

| 类别 | 检查方向 |
|------|----------|
| 类型错误 | 接口返回结构与前端类型定义不一致；`undefined` 未做防守 |
| 响应式异常 | 解构 reactive/ref 丢失响应性；watchEffect 循环依赖 |
| 异步竞争 | 多次请求结果顺序不确定；组件卸载后异步回调仍在执行 |
| 路由异常 | 守卫逻辑死循环；动态路由参数未响应变化 |
| 渲染异常 | v-for 缺 key；条件渲染与响应式状态不同步 |

### 3. 修复原则
- 只修改 Bug 涉及的最小范围代码，不顺手重构其他逻辑。
- 修复后删除调试用的 `console` 语句。
- 若 Bug 由类型不安全引起，同步补全类型定义，不用 `any` 绕过。

### 4. 验证
```bash
pnpm type-check
pnpm lint
pnpm test:unit -- run
```
如有对应的 E2E 用例，同步运行：
```bash
pnpm test:e2e --project=chromium
```

### 5. 交付格式
说明：Bug 根因、修改的文件及关键改动、验证命令输出、是否有潜在同类问题。
